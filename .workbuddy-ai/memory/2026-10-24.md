## 修复：刷新后台页被踢回首页 + 弹登录框

**实测结论**：SSR 读 `auth-token` cookie 是正常的（`next dev` 带 cookie 请求 `/dashboard`，RSC flight 里能看到 `initialToken`）。真正的问题是客户端把「SSR 没有 token」当成登出信号：

- `UserStateProvider` 里 `else if (userStore.token || user) { setToken(null); setUser(null) }`，只要 SSR 没读到 cookie（cookie 过期/被丢弃/iframe 下 SameSite=Lax 不发送），就把 localStorage 里的登录态整个清掉 → `AuthRouteGuard` 弹登录框 + `useDashboardGuard` 跳 `/`。
- 且 `useDashboardGuard` 原本 `if (!isAuthenticated || !user) replace("/")`，SSR 有 token 但 profile 补拉中也会被立刻踢走。

**改动**：
- `components/providers/UserStateProvider.tsx`：SSR 无 token 但本地有 token 时以客户端为准，并 `setToken(token)` 回写 cookie 自愈；只有本地也没有 token 才清空。补拉 profile 时打 `isProfileLoading`。
- `stores/useUserStore.ts`：新增 `isProfileLoading` / `setProfileLoading`（不进 partialize，不持久化）。
- `components/dashboard/useDashboardGuard.ts`：`isProfileLoading` 时先等待，`!user || !hasAdminRole` 才跳。

校验：`tsc --noEmit`、eslint 通过；dev 下带/不带 cookie 请求 `/dashboard` 均 200 正常渲染。

### 二轮定位：真正的根因是续期请求缺 Device-Id

用 headless Edge（CDP）+ mock/真实后端复现后确认：

1. **`refreshAccessToken` 用裸 fetch，只发了 `Content-Type`，没带 `Device-Id`。后端强制要求该头**：
   - 不带 → `400 {"message":"device-id header is required"}`
   - 带上 → 真无效才 `401 {"message":"response.error.refreshTokenInvalid"}`
   而代码把 **400 当成「refreshToken 无效」直接清空登录态**。所以只要 access token 过期（或任意请求 401 触发续期），续期必然 400 → 强制登出 → `AuthRouteGuard` 弹登录框 + `useDashboardGuard` 跳 `/`。
2. `useDashboardGuard` 把 `user === null` 等同于未授权；而 profile 可能只是暂时取不到 → 即使 token 有效也会被踢回首页。

**改动（二轮）**：
- `stores/useUserStore.ts`：`refreshAccessToken` 通过 `getRequestAuthState()` 取 deviceId 并带上 `Device-Id` 头。
- `components/providers/UserStateProvider.tsx`：profile 缺失时先补拉，失败再 `refreshAccessToken()` 续期后重试一次（续期内部会自行处理死会话），整个过程 `isProfileLoading=true`。

**排查经验**：
- 本机 `next dev` 有项目级锁，同一目录不能起第二个 dev server；改用「复制 src + node_modules junction」时 Turbopack 会报 symlink 越界，`--webpack` 能起但 hydration 不完整，不可用于复现。
- 可行方案：headless Edge（`--headless=new --remote-debugging-port=9222`）+ 原生 WebSocket 走 CDP（Node 22 自带），需要访问宿主 dev server 时加 `--proxy-server=http://127.0.0.1:<代理端口>`。

### 三轮：登录态在 SSR 就生效（全局）

**目标**：服务端渲染出来的 HTML 直接带登录态，不用等 hydration。

**不能做的**：在服务端 `useUserStore.setState()` 播种。store 是模块级单例，Next 并发渲染多个请求会串号（把 A 的用户渲染给 B），是隐私事故。所以 store 在服务端永远是初始空值。

**做法**：给 `useUserStore` 这个 hook 本身加「服务端快照回落」，45 个调用点零改动。

- 新增 `lib/auth-snapshot.ts`（**必须 `"use client"`**，否则 `createContext` 被 RSC 引入会编译报错：store 通过 `request-auth` 被服务端图引用）+ `components/providers/AuthSnapshotProvider.tsx`。
- `stores/useUserStore.ts`：`create()` 改名为内部 `baseStore`；导出 `useUserStore = Object.assign(useUserStoreSelector, baseStore)`（保留 `getState/setState/subscribe/persist`）。`useUserStoreSelector` 里：`isAuthReady` 为 false 时用 `baseStore.getState()` 合并 context 快照后跑 selector，为 true 时直接用 store 的选中值。
- `UserStateProvider`：layout effect 里播种完调 `setAuthReady(true)`；用 `AuthSnapshotProvider` 包住 children，快照为 `{ user: initialUser, isAuthenticated: !!initialUser }`（只认 profile，避免 token 有效但 profile 没拉到时 SSR 产出 `/account/undefined`）。

**实测**（探针副本 + mock 后端，`next dev --webpack`）：
- 带有效 token 的 `/`：header 内 `/account/1`×2、「个人主页」×2、「登录」×0 → 服务端渲染的就是已登录态。
- 不带 token：header 内「登录」×6、`/account/1`×0。
- `/dashboard` 200，角色徽章「超级管理员」出现在服务端 HTML 里。

**注意**：`isAuthReady` 只用来做「快照 → store」的交接，登出后不会回落到旧快照。

## 修复 hydration mismatch：HeaderTabs 频道链接 href

**报错**：`A tree hydrated but some attributes ... didn't match`，diff 为 `href="/channel/1/2"`（client）vs `href="/channel"`（server）。

**根因**：`components/home/HeaderTabs.tsx` 在**渲染期**调用 `getChannelHref()`，里面用 `typeof window === "undefined"` 分支 + 读 sessionStorage。服务端只能返回 `/channel`，客户端 hydration 首帧读到「上次访问频道」→ 属性不一致。这正是报错提示里第一条（server/client branch on `typeof window`）。

**改法**：不在渲染期分支。`useState(DEFAULT_CHANNEL_HREF)` 固定首帧为 `/channel`，把「写/读 sessionStorage」合并到一个 `[currentPath]` 的 effect 里，挂载后再 `setChannelHref`。这样服务端与客户端首帧完全一致，href 在 hydration 之后才更新（视觉无感）。

**排查经验**：全仓 `typeof window === "undefined"` 有 40+ 处，但只有 `HeaderTabs` 在渲染路径上；其余都在 effect/回调/工具函数里，不影响 hydration。判据是「这段代码是否参与 render 输出的 HTML 属性」。

**验证**：无头 Edge + CDP（脚本 `%TEMP%/hydration-check.mjs`，Edge 用独立 `--user-data-dir` + `taskkill /T` 只杀自己那份）——先 `sessionStorage.setItem('last-visited-channel','/channel/1/2')` 再 `Page.reload`，连续 3 次结果：hydration 相关日志 0 条、无 error 级日志、`/` 下频道 tab href 最终为 `/channel/1/2`。这是该 bug 的精确复现路径。
