## 批次 1（P0）执行

已改 3 处，均为最小手术式修改：
- `src/lib/rich-text.ts`：抽出 `sanitizeElement()`，白名单外标签 `replaceWith` 后对提上来的节点递归净化（修 XSS 逃逸）。
- `src/components/editor/Editor.tsx`：新增 `quillListenersRef`，effect 改为「实例已存在则重新绑定监听 + 同步 placeholder/readOnly/ref」；原来 cleanup 解绑后早退会让 `onChange` 永久失效。
- `src/lib/message-socket.ts`：`request()` 改为按 responseEvent 建 FIFO 队列 + 单一 handler（`pendingResponses` Map、`settle()`、`rejectPendingRequests()`），消除并发串台与互相 off 监听。

**P0-3（SSR 空壳）已撤回**，重要认知：
- zustand `persist` + 同步 localStorage 在**模块导入时就 rehydrate**，客户端首帧 `isAuthenticated` 已为 true，而服务端渲染空态 → 放开 `return null` 会变成 hydration mismatch。
- 在服务端用 `initialUser` 播种 store 更危险：zustand store 是模块级单例，SSR 会跨请求泄漏用户资料。
- 全仓无 `mounted` 守卫、无 auth context，缺安全锚点。正确做法是让 auth 相关 UI 读 props/context 或加 `useHydrated()`，之后才能删 `return null`。
- P0-4 未动：真修法需后端 HttpOnly cookie；只清 localStorage 副本无安全收益。

环境：仓库无 `node_modules`，无法跑 typecheck/lint/dev；仅用 `npx -p typescript tsc` 单文件做了语法级校验（过滤 TS1xxx，无报错）。运行时验证需先 `pnpm install`。

## 批次 5（P2-8：私信图片 URL 解析去重）

发现私信图片地址解析有 **4 份**实现：
- `resolveMessageImageUrl`（Pane 与 Center 各一份，逐行相同）：`urls[0] → imageUrl → url`
- `resolveMessageImageUrls`（Pane）：`urls` → 回退到上面那个
- `getMessagePayloadUrls`（Center，用于乐观发送去重）：`urls → url → imageUrl`（优先级不同）
- `resolvePreviewImageUrls`（MessageCenter.utils，私有）：`urls → url → imageUrl`

改动：全部合并到 `MessageCenter.utils.ts` 的 `resolveMessageImageUrls()` / `resolveMessageImageUrl()`，优先级统一 `urls → imageUrl → url`；Pane 与 Center 的本地实现删除，改为 import。

**重要更正**：原审计断言「优先级不同 → `matchesPendingPrivateMessage` 去重失败 → 消息重复上屏」**不成立**。复核发现去重两侧（`pending.payload` / `incoming.payload`）调用的是同一个函数，比较自洽。这不是 bug，只是重复实现。文档已更正。
