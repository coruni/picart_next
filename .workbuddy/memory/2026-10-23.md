## 批次 9（P0-3 + P1-1 + P1-3：SSR 空壳 / 布局串行取数 / 缓存失效）

### P0-3 SSR 空壳

第一版想写成 `useState(initialUser !== null || initialToken === null)`（服务端有 user 就跳过初始化门），**写完后自行撤回**：zustand persist 在模块导入时就会 rehydrate，服务端用 props 播种 store 会导致 (a) 首帧与客户端不一致 → hydration mismatch，(b) store 是模块级单例，SSR 下跨请求共享 → 用户数据泄漏。

最终做法（5 步）：
1. `useUserStore` / `useAppStore`（`app-storage` + `translate-storage`）全部 `skipHydration: true`，删掉结尾的 `as never`（这个断言在掩盖 persist 的类型）。
2. `useUserStore` 的 `logout` 返回值改成 `Promise<void>`（interface 与实现同步），原来声明是 `void` 但实现是 async。
3. `UserStateProvider` 重写：去掉 `isInitialized` 与 `return null`；改用 `useIsomorphicLayoutEffect`（`typeof window === "undefined" ? useEffect : useLayoutEffect`）在**绘制前** `persist.rehydrate()` 三个 store（user/app/translate），再用 `initialToken` / `initialUser` / `initialConfig` 覆盖，然后 `initializeInterceptors()`。
4. 鉴权头从 request 拦截器下移到 `resilientFetch`：新增 `withClientAuth(init)`（客户端补 `buildAuthHeaders`，服务端直接返回），`resilientFetch` 开头 `init = await withClientAuth(init)`。
5. `runtime.config.ts` 删掉 request 拦截器（只留 response/error），连带删 `buildAuthHeaders` / `getRequestAuthState` import。

关键认知：**request 拦截器 + `skipHydration` 是冲突的**。原来的拦截器从 store 读 token，而 store 在绘制前才 rehydrate —— 拦截器和 rehydrate 的先后顺序无法保证。把鉴权头挪到 fetch 层，token 读取时机就变成了「请求发出的那一刻」，天然正确。

服务端行为不变：只在 `initialToken && !initialUser` 时异步补拉 profile（token 有效但 SSR 取 profile 失败的情况）。
